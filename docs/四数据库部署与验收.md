# 四数据库部署与验收

业务库支持 `MySql`、`SqlServer`（兼容 `MSSQL`）、`Oracle`、`SQLite`。配置由系统配置库管理，业务数据、Fusion 原始事实、投影任务、接入租约及操作历史保存在所选关系库；配置变更历史使用独立 SQLite 文件。

## 配置与初始化

超级管理员在“系统配置”选择业务数据库并填写对应连接字符串，能够查看和编辑凭据原值。数据库类型、连接字符串、连接工厂及文件路径属于启动参数，保存后需要重启；切换提供器不会自动搬运另一种数据库中的业务数据。页面依据后端能力清单显示支持热更新的参数，环境变量覆盖值保持优先。页面不显示配置存储引擎名称。

| 提供器 | 业务连接键 | 自动初始化范围 |
| --- | --- | --- |
| MySQL | `ConnectionStrings:MySql` | 服务器级连接检查并创建业务数据库，应用 Code First 迁移 |
| SQL Server | `ConnectionStrings:SqlServer` | 服务器级连接检查并创建业务数据库，应用独立迁移程序集 |
| Oracle | `ConnectionStrings:Oracle` | 在已运行的目标 PDB 内创建业务用户/schema、授权、应用独立迁移程序集 |
| SQLite | `ConnectionStrings:SQLite` | 解析内容根目录下的文件路径，自动创建缺失目录和数据库文件，应用独立迁移程序集 |

首次部署示例，密码和服务器地址需替换为目标环境的实际值：

```text
MySql: Server=mysql;Database=sorting_hub;User Id=业务用户;Password=实际密码;
SqlServer: Server=sqlserver;Database=sorting_hub;User Id=业务用户;Password=实际密码;Encrypt=True;
Oracle: User Id=SORTING_HUB;Password=实际密码;Data Source=oracle:1521/FREEPDB1;
SQLite: Data Source=data/business/sorting-hub.db;Default Timeout=30;Foreign Keys=True;
```

Oracle 的实例、PDB 和监听服务由数据库部署提供；应用自动建库对应 PDB 内的业务 schema。首次创建 schema 需要 `ConnectionStrings:OracleAdministration` 指向同一 PDB，具备创建用户、授权及授权 `SYS.DBMS_LOCK` 的权限。隔离验收使用 `SYS`/`SYSDBA`；现有生产 schema 可由 DBA 预建和授权，程序后续只使用业务连接执行迁移与写入。业务账号需能建表、序列和触发器，以及执行 `SYS.DBMS_LOCK`。已有用户缺少锁包权限时，管理连接探测会发现并在建库守卫授权后补齐。目标 PDB 无法连接时不会假定建库成功。

SQLite 拒绝内存业务库，相对路径以服务内容根目录为基准。默认超时 30 秒，启用 WAL 与 `PRAGMA optimize`；文件及所在目录需要服务账号可写。只读连接自动使用 `Mode=ReadOnly`，连接或健康探测不会建立缺失文件。Docker 必须持久化整个数据库目录，包含 WAL/SHM 文件，不要只挂载主 `.db` 文件。

实际初始化遵循现有守卫：

```text
Persistence:DatabaseBootstrap:EnsureDatabaseExists:Enabled = true
Persistence:DatabaseBootstrap:EnsureDatabaseExists:Isolator:AllowDangerousActionExecution = true
Persistence:DatabaseBootstrap:EnsureDatabaseExists:Isolator:EnableDryRun = false
Persistence:MigrationGovernance:DryRun = false
Persistence:Sharding:WriteRouting:AllowTableCreation = true
Persistence:Sharding:WriteRouting:DryRun = false
```

生产危险迁移阻断默认保留。连接失败或模型版本未知时记录错误并保留原库；`FailFast` 和降级策略仍由部署配置决定。上述开关只放行对应操作，不会覆盖生产迁移守卫。

## Code First、分表与调优

四种提供器复用一个上下文工厂，各自维护 EF Core 9 的迁移和模型快照。业务表、约束、索引、物理分表及历史分表结构升级由 EF 模型差异、迁移操作和提供器 SQL 生成器执行；SQLite 表重建交给 EF 迁移执行器。原生 SQL 保留于建库/schema 授权、数据库锁、元数据探测、统计信息维护，以及 EF 不支持的窗口统计。Oracle 使用 21 兼容级别和可逆空字符串编码，正文为 NCLOB，业务原文及 SHA-256 保持不变。

2026-10-08 的 `AddSourceStageDurationIndex` 迁移在四库均新增来源、阶段、固定分表时间及耗时端点的覆盖索引。旧阶段索引继续支持无来源筛选，历史事实物理表由启动维护自动补齐。MySQL 的两种耗时索引使用 `ALGORITHM=INPLACE, LOCK=NONE`，无法在线创建时明确失败，不回退为阻塞业务写入的 DDL。四库实际启动升级及后续查询验证见 [Fusion 联合回归验收](Fusion联合回归验收.md) 和 [查询性能验收](查询性能验收.md)。

同日的 `AddDwsWindowBoundaryIndex` 在四库新增 DWS 测量时间、阶段和成功标记索引 `IX_Dws_Time_Stage_Success`。原有索引保留，历史物理分表自动补齐；MySQL 复用在线索引生成器。验收在维护工具执行写入之前，纯读取确认宿主已应用迁移并补齐事实与 DWS 索引。

包裹分表和请求审计分表支持自动预建和运行时创建。不同进程使用数据库锁；SQLite 使用同一数据库目录内的排他锁文件。建表完成后才记录目录及 `PartitionSchemaVersions`。启动时将旧版本物理表升级至当前模型；无版本目录的旧表根据历史模型列集合识别，并补齐缺失索引。未知结构不推测覆盖，需先核对历史迁移和实际列。

历史分表升级记录前向 DDL、新增索引的回滚 DDL及结构变更需备份的标记，并遵循建表预演、迁移预演及生产危险操作守卫。不会自动执行回滚；涉及列或表的数据结构回退需使用验证过的备份和迁移回退方案。

自动调优复用原有慢查询预算、隔离器和观测管线：四库均能生成并执行索引调优，MySQL 使用 `ANALYZE TABLE`，SQL Server 更新统计，Oracle 使用 `DBMS_STATS`，SQLite 使用 `PRAGMA optimize`。生产是否自动执行仍由原有调优隔离配置决定。Oracle 和 SQLite 的备份提供器生成原生工具运行手册；它们不代表已执行完整备份和恢复演练。

Oracle/SQL Server 同票处理先通过 EF 更新锁住全局定位行，再读取历史和更新快照，避免跨实例丢失更新。新票唯一键竞争、死锁和 Oracle 串行化冲突重试整个事务；凭据、事实和快照始终一起提交。Fusion 去重分别按事实编号和来源序号的唯一索引读取有界凭据，仅查询主键、编号、序号及摘要，再在内存合并双重命中；原文和投影大字段不进入去重查询，也不执行嵌套集合查询。

配置密钥现在保存在实际配置数据库目录下的 `data-protection` 子目录。启动自动复制旧 `logs/data-protection/*.xml`，保留原文件且不覆盖目标密钥。升级和备份应整体保留配置目录、配置历史目录、图片对象和业务库，确保容器重建后仍能解密已有 Fusion 凭据。

## 扩展业务模拟与故障验收

扩展模式用每库 200 票覆盖 19 种设备及 WCS 场景：正常分拣、相同条码、乱序、重复帧、HTTP 故障、格口不一致、协议噪声、来源暂时停用、无条码、TCP 分片、重试恢复、WCS 超时、非法响应、部分测量、拒绝扫码、FIFO 绑定、DWS 超时、迟到 DWS 及分拣机异常。它仍运行真实 Fusion 进程，设备与 WCS 为模拟器。

服务端数据库再发送 30 票断网、30 票数据库进程崩溃、60 票 Hub 处理中断、30 票 Fusion 积压后崩溃及 10 票普通重启后的业务，共 360 票。SQLite 使用 40 秒 EF 写锁覆盖 busy 超时，再测试两个进程中断及普通重启，共 330 票。强制中断前先确认落格记录已提交 Fusion 本地历史，随后检查待确认事实积压，避免把仍在设备网络缓冲区的帧误当成已持久化事实。每个步骤均保存故障状态、恢复状态和耗时，异常退出恢复本轮专属容器和网络。

断网时以本轮专属休眠容器暂占旧地址，数据库动态重接后必须获得不同地址，服务别名保持不变。恢复后删除占位容器；数据库不设置静态 IP，以便后续崩溃重启继续由 Docker 管理地址。验收记录前后地址并强制断言变化，防止恢复原地址掩盖旧连接故障。

三种服务端数据库先在临时验收进程使用错误密码，必须得到明确的驱动拒绝；宿主配置保持原值，随后用有效连接完成业务核对。SQLite 临时进程使用独立缺失路径和 `Mode=ReadOnly`，必须拒绝打开，且不得创建目标目录或文件。`--probe-connection` 只打开和关闭连接，不执行迁移或维护；正常验收入口继续强制检查 Code First 模型和迁移历史。

MySQL 的临时错误密码检查使用 `SslMode=Required`，让 `caching_sha2_password` 完整认证到达服务器凭据拒绝阶段；本轮业务仍使用 Compose 中原有连接，覆盖冷重启后的实际接入。不会启用不受信任的 RSA 公钥获取。驱动认证传输说明见 [MySqlConnector 认证传输](https://mysqlconnector.net/troubleshooting/retrieval-public-key/)。

协议异常工具每库执行 28 项断言，涵盖凭据隔离、登记身份不一致、有效租约竞争、混合正确与错误事实、编号和序号冲突、32 个并发重复重放、超限批次、过期租约、损坏图片块、错误偏移、图片内容冲突、实例重建后的断点续传，以及超过 JavaScript 安全整数范围和 Int64 最大值、4096 字中文正文、换行、引号、控制字符、emoji、空值及空字符串的原样往返。工具使用独立来源和测试对象，不删除已有历史。它复用已验收 Fusion 报文的协议时间，所以空库应先完成一轮真实 Fusion 联调。

修复后的接收查询不读取原文大字段进行去重。Oracle 连接在建立前统一启用 TCP keepalive，空闲 30 秒开始探测，未确认探测间隔为 3 秒；管理连接使用相同策略。命令超时与 TCP 存活检测处理不同的等待，官方说明见 [Oracle 命令超时](https://docs.oracle.com/en/database/oracle/oracle-database/26/odpnt/ConnectionCommandTimeout.html) 和 [Oracle TCP 存活检测](https://docs.oracle.com/en/database/oracle/oracle-database/26/odpnt/ConnectionKeepAlive.html)。SignalR 故障日志在请求上下文已释放时保留连接身份和原始异常，不让日志采集替换实际故障。

SQL Server 的 EF 执行策略遇到连接、结果读取或事务中的网络及超时错误时清理当前配置对应的连接池，并识别 Linux 驱动内层套接字错误；有界节流避免并发清理风暴。在用连接归还时淘汰，恢复仍遵循原提供器的可重试异常集合和等待预算，由 Fusion 耐久重放处理未确认事实。约束、死锁和凭据错误不触发清理，正常请求不增加探测 SQL 或连接往返。语义见 [SqlClient 连接池恢复](https://learn.microsoft.com/en-us/sql/connect/ado-net/sql-server-connection-pooling?view=sql-server-ver17#manage-connection-lifetime-and-clearing)。

Oracle 同样在 EF 结果读取及事务中的 TNS/断线异常返回前清理关联池，避免失效连接归还时继续在旧地址进行会话复位。Oracle 策略最大重试次数为零，继续由已有业务事务和 Fusion 发送库决定重放；凭据错误和普通取消不清理池。两种提供器共用错误识别、固定大小节流与日志实现，不增加正常请求往返。

2026-10-08 的连续故障验收发现：Oracle 使用单主机 Easy Connect 地址时，断网及地址变化后的再次重启可能使原进程持续报 ORA-12154；数据库已经健康，独立的新连接却能成功。仅清理连接池不足以恢复。业务及管理连接现在在 EF 配置入口将普通单主机 TCP 地址转换为等价的标准连接描述符，保留主机、端口、服务名和全部连接选项，不查询 DNS 或建立探针连接。TLS、钱包、集群、IPv6、TNS 别名和带附加参数的地址保持原配置。转换依据见 [Oracle Easy Connect 与连接描述符](https://docs.oracle.com/en/database/oracle/oracle-database/26/netag/understanding-easy-connect-naming-method.html)。连续断网、动态地址变化及强制重启复验已恢复；完整联合验收结果见本轮验收记录。

资源有限的本机应按提供器顺序执行，并停止本轮不使用的验收数据库；四套数据库、四套 Hub、四个 Fusion 与已有服务同时运行的结果不能用来代替单库接入验收，也不能作为生产吞吐承诺。以下命令在已经启动并复制最新工具的单库环境执行：

```powershell
python tools/DatabaseVerification/fusion_database_matrix.py --provider oracle --count 200 --batch-size 40 --extended-scenarios --faults --output .codex-artifacts/database-exceptions
docker exec zeye-db-verification-hub-oracle-1 dotnet /app/verification/DatabaseVerification.dll --protocol-faults
```

将提供器和容器名依次替换为 `mysql`、`sqlserver`、`oracle`、`sqlite`。崩溃会留下默认 120 秒的来源及投影保护租约，恢复等待最多 240 秒；等待租约到期保护并发实例所有权，不通过清除租约强行接管。最终必须全部确认、无拒绝和舍弃、逐条事实与图片一致、无重复包裹及未完成投影，超时或不一致均判为失败。
