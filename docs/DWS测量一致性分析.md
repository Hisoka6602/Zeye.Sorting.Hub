# DWS 测量一致性分析

入口：包裹中心 → DWS 一致性（`/parcels/dws-consistency`），使用 `parcels.read` 权限。
只读接口：`GET /api/parcels/dws-consistency`，具有中文业务说明。

## 使用

选择入库日期及可选来源工作台、实例，查看重复条码差异排行。点击“测量对比”，查看重量、物理体积及扫码耗时的最小值、最大值、中位数、极差、时间趋势、来源对比及逐次测量明细。扫码耗时同时展示平均值与 P95，可按相对差或 P95 排序。已有 Hub 包裹编号的量测可进入原包裹详情。

“偏差阈值与标准参考值”内可调整容差。默认重量 20 g / 2%，物理体积 100 cm³ / 3%，扫码耗时 50 ms / 20%；绝对差和相对差均超过阈值才标记超差。相对差以本组中位数为基准，非正基准时保持未知。阈值是当前分析参数，不代表设备的额定精度或规定响应时间。

指定精确条码后，可以填写已知标准重量和体积。参考偏差与重复测量波动分别展示，标准值只用于当前查询。未提供标准值时，仅判断稳定性，不能证明测量准确度。

## 数据口径

- 条码精确匹配、区分大小写。相同条码的不同包裹保留各自身份，不合并业务包裹。
- DWS 接收与绑定按来源实例、运行会话、MessageIdentity 合并，一次物理量测只计一次。缺少完整身份、身份下数值/条码/关联包裹/测量时间冲突的记录排除并展示计数。
- 重量使用克，体积使用物理体积（立方毫米换算为立方厘米）或完整尺寸；体积重量不当作体积。缺失指标不补零，真实零重量保留。至少两次有效指标样本才计算极差。
- 扫码耗时按完整来源实例、运行会话、设备包裹号及 Hub 包裹编号关联真实 `Detected.OccurredAt` 与带有效条码的 `DwsReceived.ReceivedAt`。缺少显式来源接收时间时使用该来源接收事实的 `OccurredAt`，在明细标明端点来源；不使用 `MeasuredAt`、绑定时间、Hub `RecordedAt` 或外部扫描上传调用时间替代。该口径反映检测到有效条码可用的响应过程，包含设备安装位置和传输影响，现协议未单独采集解码芯片内部耗时。
- 没有明确包裹关联、接收与绑定的来源包裹号冲突、缺少接收/检测记录、时间不可靠、端点冲突或时间倒序的样本，其扫码耗时保持未知并展示原因；重量和体积仍独立有效。只有绑定阶段才补齐条码时，不能推断接收阶段已经取得条码。真实 0 ms 有效，不制造零基准百分比。平均值、中位数及最近秩 P95 使用全部有效扫码样本。
- 日期使用现有不可变分表锚点：已关联记录沿用包裹入库日期，未关联记录沿用记录入库日期。晚到绑定不会因发生时间跨日丢失。重量和体积趋势仅绘制真实设备测量时间；扫码趋势独立使用有效条码接收时间，设备测量时间缺失不会丢弃有效扫码样本。
- 来源表示工作台实例，尚无独立 DWS 设备编码。跨来源比较先按共有条码计算各来源中位数相对总体中位数的绝对偏差，再取偏差中位数，不混合不同包裹大小的总平均。
- 同条码不一定是同一物理包裹；包装变化、条码复用或不同量测姿态都需要结合原始记录核查。

## 查询和存储

使用 EF Core 无跟踪、分表窄列查询，不读取原始报文大字段，扫码统计沿用现有采集字段，不修改量测写入热路径。最长 31 天、最多 20 万条候选量测记录及 20 万条相关检测记录；超限要求缩小范围，避免不完整统计。扫码仅读取相关包裹的检测标量事实，小总体使用编号 IN 筛选，大总体每个分表流式扫描一次并校验完整来源身份。最多一分钟的有界内存快照，调整阈值、条码和分页复用快照，显式刷新重新读取。排行和明细每页 20 项；每种趋势最多 200 个真实点并保留首尾，汇总始终使用完整有效总体。
