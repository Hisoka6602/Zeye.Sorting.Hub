## 正式接口读写与权限

每库使用正式接口通过以下检查组：

- 8 组业务读取：分页及大整数身份、分析总量、全部耗时类型与分布、同条码时序和对比、DWS 一致性、详情和三图浏览、工作台与未关联事实及游标、非法参数和不存在编号。
- 5 组业务写入：创建及完全重放、变更报文冲突、更新和删除；异步批量入队实际落库；规则旧版本冲突及系统兜底保护；归档演练完成和重试；登录密码确认清理及永久操作汇总。
- 8 组身份权限：普通业务读取、受限读取、受限写入、匿名拒绝、机器 Hub 拒绝浏览器会话、自我提权拒绝、内置账号隐藏和保留名不区分大小写、真实 SignalR 读取与写入授权。

清理检查每库仅创建并删除两票专属旧日期案例，永久历史包含操作人、条件、数量和结果，不含逐票清单、条码或密码。4 票 CRUD 和入队临时包裹在检查完成后删除。自定义角色即使得到全部可配置权限，也不能进入测试数据、数据治理和可观测性；已建立 SignalR 连接的用户被停用后也不能继续调用。临时普通账号最终停用。

配置检查包含管理员读取原值、热更新、旧版本保存返回 409、历史持久化，结束后恢复原配置。首次管理员创建、内置超级用户、备份及恢复边界、部署脚本、清理、业务分类和慢查询优化等同时由完整回归覆盖；备份读取及演练检查不代表已执行 Oracle 原生整库导出和恢复。

## 本轮发现并修复的问题

Oracle 的普通单主机 Easy Connect 地址在断网、地址变化后再次重启时，长时间运行的进程可能持续报 ORA-12154，新进程却能连接。第一轮清理连接池修复不足以解决问题。最终在 EF 和管理连接配置入口将明确的单主机 TCP 地址转换为等价的标准描述符；复杂地址、TLS、钱包和 TNS 别名继续交给驱动。转换为纯内存操作，不增加正常查询的 DNS、数据库或文件访问。11 项专项回归及实际连续故障复验通过。

浏览器检查发现包裹详情长条码换行后，固定高度框会覆盖下一行。框改为最小高度并随内容增高，复制按钮保持可用。1280、820、390 像素宽度均检查框内内容、下一行位置和页面宽度，无裁切、重叠或横向越界。

处理事实统计将成功与失败分组改为一次常量分组聚合，在一次覆盖扫描中统计总量、失败及未关联 DWS，避免按成功标记排序分组；DWS 单次测量直接计算指标，来源统计复用已有结果。按来源查询阶段时新增 `IX_Processing_Source_Stage_Duration`，四库各有独立 EF 迁移，启动自动维护历史物理分表。每库纯读取确认五张事实表的索引，未通过手工修改业务 SQL、索引提示或关闭慢查询采集获得结果。MySQL 的实际执行计划由大量来源回表变为覆盖索引读取。性能详情见 [查询性能验收](查询性能验收.md)。

大总体的单次 EF 结果读取仍会形成慢查询，因此新增按时间划分的读取窗口。普通事实目标为 4,096 行，DWS 测量和检测目标为 8,192 行；通过索引查找下一窗口的时间边界，避免递归计数反复扫描大范围。窗口直接枚举 EF 查询，使用完整毫秒的半开时间范围，保留密集同毫秒数据、跨日数据和全部有效样本。阶段查询只选择十个必要字段，移除八个无用的空值投影。Oracle 使用专属只读查询拦截器调整驱动取数批次，目标 1,024 行，额外取数内存上限为 2 MiB；显式配置的更大批次保持原值。DWS 身份解析、缺失条码分组和冲突检查减少重复分配。新增窗口完整性、四库 SQL 翻译、稀疏跨日查询次数及取数边界回归。

中间部署在正式数据下暴露了额外瓶颈：DWS 一致性约 2.5 秒、200 次命令，窗口计数扫描最高 1,718.81 ms；一次读取 7,464 行的接口耗时查询达到 584.25 ms。原始失败证据已保留。此次继续改为索引时间边界读取并缩小窗口，同时为 DWS 测量增加 `IX_Dws_Time_Stage_Success`。四库独立 EF 迁移与历史分表启动维护补齐索引，验收先纯读取检查，未使用手工建索引来替代自动升级。

进一步在正式 49,745 票总体复验时发现多阶段条件仍会增加边界排序成本；阶段读取改为分别沿阶段等值索引划分窗口，在内存按原有来源身份和端点规则合并。72 项耗时、DWS 及窗口专项通过，完整回归与四库原始数据复验通过。中间部署自动创建历史 DWS 索引耗时 2.37 秒，按启动 DDL 单独保留，不能将其冒充已解决的业务查询或清除记录。

15 次完整故障注入使用同轮保留的原始结果；最后的查询读取优化另在四库重跑了启动索引检查、28 项协议断言及正式业务读写、配置和权限验收，逐条对账保留的 Fusion 事实和图片。未把旧故障恢复耗时标为最后一次查询修复后重新测得。

失败证据保留，包括两轮 Oracle 连接恢复失败。测试脚本对公开包裹状态值的错误断言、图片放大按钮选择器和 React 加载等待竞态也已修正；通过结果来自修正后的重新执行，没有清除失败记录或将失败计入通过数。

SQLite 与隔离备份服务同时运行时曾有一次 DWS 一致性达到 556 ms；保留 `sqlite-performance-concurrent-backup.log`，停止备份服务后按单库流程重新执行全部 22 项，稳态上限为 371 ms。备份内容核对脚本需要显式请求 `includeTotalCount=true`，默认不计算总数的列表不能用于总数断言。

部署期间 Docker 数据盘空间耗尽，首次 Windows TRX 文件被截断，未作为有效回归证据。迁移旧构建缓存、回收无引用构建缓存及修复残留运行时 socket 后重新运行完整回归；有效 TRX 可完整解析。没有删除数据库、数据卷、图片或原始故障证据。部署监听脚本同期仅将 Compose `prune=false` 改为 `prune=true`，补充验证 PowerShell 语法、当前 Compose 参数和正式配置；源码摘要确认除此之外已验收代码未变。
